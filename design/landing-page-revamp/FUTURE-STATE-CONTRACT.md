# Future-state design contract

The user requested that mockups assume the complete [product rebuild plan](../../docs/PRODUCT_REBUILD_PLAN.md) has been implemented successfully. This supersedes the earlier current-features-only prompt constraint. These are hypothetical successful states; repository runtime remains unrebuilt.

## Landing feature story

| Moment | Future product capability |
| --- | --- |
| Hero | Structured brief, readable document, included source records, confirmed save state and history access |
| Expansion | The same workspace becomes a full-screen demo |
| 01 Shape | Audience, purpose, tone, starter structure and editable outline |
| 02 Research | Source-backed generation; inspect, include/exclude or add sources |
| 03 Refine | Original/suggested comparison, accept/discard, meaningful autosave and checkpoints |
| 04 Present | Reviewed output, document/slide preview and format-appropriate theme/export |
| Normal page flow | Brief, sources, reversible editing, history, stop/resume generation, output examples, FAQ and image-led close |

Dense composition does not require every product setting in the hero. Show the relevant useful controls at a readable scale, with rich mythological imagery around them.

## Product boundaries

- No real-time collaboration, paid autonomous agent, infinite generation, fake endorsements, fabricated performance metrics or source confidence scores.
- Sources represent records with real titles and URLs, not a customer-logo strip.
- Save confirmation must correspond to persistence in implementation; restore creates a new version.
- Report and deck remain distinct reviewed project workflows. Report-to-deck creates a new project; no costless instant format swap.
- Document export may show DOCX, Markdown, HTML and Print. Presentation export shows PPTX. Print does not promise server-side PDF download.
- The successful state can omit quota/service banners. Actual free-tier implementation still needs the plan's failure, limit, retention and recovery states.

## Comparison consistency

All five directions have the same promise, project and four-chapter expansion/pin/release sequence. Each contains four separate laptop viewports: hero, full-screen refinement state, capability grid and outputs/FAQ/close. Palette, medium, mythological scene and crop distinguish the directions.

The UI uses modern plain-English labels. Mythology stays in original decorative art. Raster references are design artifacts, never the implemented interactive interface.
